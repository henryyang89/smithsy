# Smithsy 2.0 — implementation plan (authoritative)

This is the one plan for 2.0. It merges the world, combat and UI specs and the critique (all in the session
scratchpad `v2/`), resolves their conflicts, and adds what they left open. Where this plan and an older spec
disagree, **this plan wins**. Implementers do not edit this file: if something here turns out wrong, note it under
"Plan deviations" in `HANDOFF.md`, pick the closest reading that keeps the tests honest, and carry on.

Contents
1. Decisions the user still has to make
2. Request map: R1-R46, A1-A4 → decision → batch
3. How the spec conflicts and the critique were resolved
4. Final design by area
5. `js/config.js` for 2.0 (paste-ready blocks)
6. State shape 2.0
7. Files and functions (new / changed / deleted)
8. `tools/balance.mjs` 2.0 (sections, personas, CLI)
9. Balance targets and the command that measures each
10. Implementation batches 1-7 (sequential)
11. 1.2 tests that are expected to change, and why
12. Ambiguities and the readings chosen
13. Changes the user did not ask for (FYI, each easy to undo)

House rules for every batch
- One implementer at a time, in batch order, in one tree. Never start batch N+1 before batch N is "done".
- `npm test` must be green at the end of every batch, `node tools/balance.mjs --quick` must exit 0, and the UI
  render smoke test (added in batch 1) must pass. The game must stay playable after every batch.
- Tests never hard-code a CONFIG number: derive it from CONFIG or pin it with `cfgWith` (tests/helpers.mjs).
- A failing 1.2 test is only changed when section 11 lists it (or it clearly tests something this plan removes).
  Never loosen a test just to make it pass; if a listed test fails for a reason not given in section 11, stop and
  find out why.
- Player-facing text is plain English, numbers are whole or one decimal, and hover details also work on touch
  (the `tip` helper, batch 2).
- Every new number goes into `js/config.js` with a comment. UI-only constants (debounce delays, pixel sizes) stay in
  the UI code.

## 4. Final design by area

### 4.1 Version and saves (A1) — B1

- `js/version.js`: `export const VERSION = '2.0';`
- `js/core/game.js`:
  ```js
  export const saveKeyFor = (v) => `smithsy-save-${v}`;
  export const SAVE_KEY = saveKeyFor(VERSION);          // 'smithsy-save-2.0'
  export const BEST_KEY = `smithsy-best-${VERSION}`;    // 'smithsy-best-2.0'
  // Keys of saves from other versions (to word a one-time note; never read). Backups are excluded.
  export function oldSaveKeys(keys, current = SAVE_KEY) // keys.filter(k => /^smithsy-save-/.test(k) && k !== current && !k.startsWith('smithsy-save-backup-'))
  export function serialize(state) { return JSON.stringify(state); }
  export function deserialize(text, cfg = CONFIG)       // JSON.parse; throw unless s.version === VERSION; then assertShape(s, cfg)
  function assertShape(s, cfg)                          // throw if skill keys != skillDefs keys, intel.spent keys != config tracks,
                                                        // or (from B4) s.groups is missing. Same-version saves only; dev safety net.
  ```
  `newGame` sets `version: VERSION` (string). **Deleted:** `SAVE_VERSION`, `LEGACY_SAVE_KEYS`, `migrateV1`,
  `migrateV2`, `addMissingKeys`.
- `js/main.js` `load()`: read `SAVE_KEY` only. No save → if `oldSaveKeys(allKeys).length`, set
  `startupNote = 'Smithsy 2.0 starts a fresh game: saves do not carry over between versions. Your older save is still in this browser and opens again in that version.'`
  A save that fails to load is copied to `smithsy-save-backup-<time>` (as now) and a new game starts.
- Release rule (HANDOFF step 6): "Saves are per version. Bumping `VERSION` starts every player fresh and leaves the
  older version's save in the browser. A code-only fix that does not change the save may keep `VERSION`."

### 4.2 World map and fields (R2, R3, R29, R37, R25) — B1

- `generateMap`: up to 500 attempts; reject if any field is unreachable or `dist − (|x−cx| + |y−cy|) > map.maxDetour`.
  Measured: 40 fields; per distance ~3.5 / 6.3 / 8.9 / 9.8 / 7.6 / 3.8 (+0.2 at 7); ~1.65 attempts per map.
- `distanceRow(dist, cfg) = cfg.field.byDistance[clamp(dist, 1, length) − 1]`; every reader of field contents uses
  it (map.js, help.js, mapview.js, balance.mjs).
- `rollCell(rng, dist, cfg)`: debris as now; loot chance `row.loot (+ debrisLootBonus)`; each item
  `t = rng.chance(row.gemShare) ? 'gem:' + weighted(gemWeights) : 'ore:' + weighted(row.ores)`,
  `d = round1(rng.float(0, 100))`, `s = rollSight(rng, t, cfg)`. Cell = `{ debris, boulder: false, searched: 0, items, touched: false }`
  (`revealed` deleted).
- `generateField`: 81 cells, then exactly `row.boulders` random cells become boulders.
- Search formulas unchanged; numbers 30 ± 5 %, 25 min + 2 min per fresh cell. Expect ≈ 3.98 searches per clear cell
  at +0% (2% need 3), 3.44 at +12%, 3.0 at +32%. The UI draws 9 plots with a wider gap; any cell may still be a
  search centre; default selection = the first plot centre (index (1,1), label "(2,2)").
- Regrowth: delete `regrowFields`, `field.regrowPctPerDay`, the `confirmPlan` call and log line, the Help/map rows,
  README lines 103/169/271, the balance-tool what-if and notes.

### 4.3 Sight (R31) — B1

- `field.sight` ranges `[lo, hi]`: an item's threshold is `rng.int(lo + 1, hi)`: copper 1-40, iron 11-60, coal 21-70,
  every gem 21-80, mythril 41-100.
- `sightValue(state, cfg) = intelValue(state, 'oreSight') + smithRingTotals(state).reveal` (also `smithBonuses().sight`).
- `isSeen(item, sight) = item.s <= sight`; `seenItems(cell, sight)`; `sightShare(t, sight) = clamp((floor(sight) − lo) / (hi − lo), 0, 1)`.
- Seen only in the field you stand in; sight sees through debris; nothing is stored; nothing is shown about unseen
  items; the world map shows nothing about seen items. Day 1: sight 0 → nothing seen.
- Map UI (mapview.js):
  - Field header: `[bar] 34% searched · 12 cells done · 9 under debris · 3 boulders · 7 items seen · 40 fresh · 6 in the pile`,
    then a chip `Sight 30` with tip: `Sight 30 = Ore sight intel 20 + rings 10. Every item in the ground has a sight
    threshold; you see it once your sight reaches it: copper 1-40, iron 11-60, coal 21-70, gems 21-80, mythril 41-100.
    With sight 30 you see about 75% of the copper, 40% of the iron, 20% of the coal, 17% of the gems and no mythril.`
  - Grid: 3x3 plot `div`s (`mv-plot`, 6 px gap between plots, 2 px inside) when `size % 3 === 0`.
  - A cell with seen items shows the rarest seen item's tag and `+N` for more (class `mv-seen`); tip
    `Seen (sight 30): Iron ore, Ruby. Items above your sight stay hidden until found.`
  - Selected-cell panel: chips of seen items, or `Nothing seen (sight 30).`; done cells `Fully searched: nothing hidden left.`
  - Camp panel rows: Now · Walking (`15m per step, +2% per carried item`) · Searching (`25m per 3x3 area, +2m per fresh
    cell; each search digs 25-35% deeper into every cell, so about 4 searches finish a cell`) · Sight · Debris
    (`about 15% of cells, 20-60 thick; 2-4 boulders per field, more far away`) · Field piles · Reachable. The
    "Ore sight" chance row and "Regrowth" row are deleted.
  - "What the fields hold, by distance" (`<details>`, closed): Distance | Fields | Walk out/back | Cells with items
    (debris) | Boulders | Items/field | Cu | Fe | Co | My | Gems (% of items found at that distance). Note: "Fields
    farther than 6 steps use the distance-6 row."
  - Legend: "Seen item" swatch replaces both "Revealed" swatches; "done" swatch reads "Fully searched: nothing hidden left".

### 4.4 Skills (R4, R5, R34, R35, R36, R43, R18) — B2

**Model.** Each skill has `effects: { effectKey: amountPerLevel }`. One XP curve (100 × (L+1), max 10; 5,500 XP total).
Activity skills count for every material; per-material skills only for their own bar or gem type.

**The 35 skills** (9 activity + 4 per bar × 4 bars + 2 per gem × 5 gems):

| Key | Name | Group | Per level | XP |
|---|---|---|---|---|
| `travel` | Travel | Travel and fields | 0.6% less travel time (every trip) | 15 per map step walked |
| `carrying` | Carrying | Travel and fields | 5% less extra time per carried item | 2 per item carried one map step |
| `searchTime` | Search speed | Travel and fields | 0.6% less search time | 1 per minute searching |
| `searchEff` | Search efficiency | Travel and fields | 1.2% more searched per search | 1 per minute searching |
| `debris` | Debris clearing | Travel and fields | 10% more debris cleared | 1 per debris point cleared |
| `refineTime` | General refining | Workshop | 0.6% less refining time; 0.1 pts less refining failure (every bar) | 1 per minute refining |
| `cutTime` | General cutting | Workshop | 0.6% less cutting time; 1% better cutting chances (every gem) | 1 per minute cutting |
| `repairTime` | General repair | Workshop | 1% less repair time (all gear) | 1 per durability point repaired × bars in the item |
| `gearCare` | Gear care | Workshop | 1% less durability loss | 100 per fight survived |

**Margin (core/sim.js):**
```js
// Shown "±": twice the spread of the per-guess results, but never less than the gap between the result and the
// Wilson bound (z = 2) of all test fights on the side that matters. 25 wins of 25 -> 14, not 1.
export function shownMargin(res) {
  const n = res.fights; if (!n) return null;
  const p = res.wins / n, z = 2, d = 1 + (z * z) / n;
  const c = p + (z * z) / (2 * n), r = z * Math.sqrt((p * (1 - p)) / n + (z * z) / (4 * n * n));
  const gap = p >= 0.5 ? p - (c - r) / d : (c + r) / d - p;
  return Math.max(1, Math.round(2 * res.se), Math.round(100 * gap));
}
```

### 8.3 Personas (B6) — tool settings, so they live in tools/balance.mjs

```js
export const PERSONAS = {
  careful: { name: 'Careful planner', pick: 'ev', minWin: 90, future: 1000,
    intel: [['enemySight', 40], ['simDepth', 3], ['groupSight', 50], ['oreSight', 30], ['*']],
    pack: 'score', rings: 'value', restBelow: 40, repairBelow: 60, subBelow: 30, trips: 5, minRate: 0.003, carry: 'value', swordBias: 1 },
  champion: { name: 'Champion hunter', pick: 'champion', champMin: 70, eliteMin: 80, future: 150,
    intel: [['simDepth', 3], ['enemySight', 40], ['ringTypeSight', 49], ['*']],
    pack: 'score', rings: 'value', restBelow: 0, repairBelow: 30, subBelow: 15, trips: 5, minRate: 0.003, carry: 'value', swordBias: 1.5 },
  casual: { name: 'Casual', pick: 'looks', gearLevelForElites: 6, intel: 'roundRobin',
    pack: 'default', rings: 'grade', restBelow: 0, repairBelow: 30, subBelow: 0, trips: 2, minRate: 0.003, carry: 'default', swordBias: 1 },
};
```
- Intel list: spend on the first entry whose track is below its target and can gain; `'*'` (and `roundRobin`) = the
  track with the fewest points that can still gain (config order on ties). Always spends every point.
- `pickEnemy(P, st, evals)` (exported, pure; `evals = [{ i, tier, p, ev }]`):
  careful: among `p ≥ minWin` the max `ev`; none → max p. champion: champions with `p ≥ champMin` → highest p; else
  elites with `p ≥ eliteMin` → highest p; else max `p/100 × (score + future)` over `p ≥ 50`; else max p. casual: never
  computes p; `G = gear types owned + gear types owned in iron or better` (0-10); `G < gearLevelForElites` → normals,
  else normals and elites; fewest **visible** High attributes, ties → lowest index; never champions.
- Packing: `score` = top `packLimit` by bot score after the rest rule; `default` = the game's `defaultPack`.
  Rings: `value` = `pickRings` (current); `grade` = highest ring value first, any type. Crafting: the shared engine for
  all three (`swordBias` multiplies the sword slot weight). `trips` caps trips per day; `carry` as the 1.2 flag.
- `--persona all` (benchmark default) runs each persona on the same seeds; `--jobs` shards each persona.
